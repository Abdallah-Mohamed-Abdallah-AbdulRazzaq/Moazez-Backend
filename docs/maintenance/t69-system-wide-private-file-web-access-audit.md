## Evidence and accounting

It confirms those two browser compatibility gaps, but cannot establish whether redirect handling, forwarded authorization, provider CORS, response handling or browser preview support caused the failure.

The complete source search covered Redirect/307, signing, object reads, private-content helpers, Range, presenter file URLs and file metadata. The pre-edit main transport inventory has **23** entries: 14 signed 307 routes, 3 private-content routes, 3 native-playback capability routes, public branding, credential export and one curriculum metadata route. The candidate has **41** entries: the same 14 redirects and 3 existing private-content routes, **18 new private-content routes**, and the same 6 other contracts. GET counts are distinct registered paths; framework-generated HEAD support is not double-counted. Metadata consumers below are counted separately.

Two incident routes are confirmed; twelve other legacy redirects are potential instances of the same transport class and are disposed by either an existing or new authorized direct-content alternative. Seven other actor consumer contexts emit a generic Files URL that their actor is forbidden to use: Student avatar, Student/Parent catalog images, Student/Parent redemption-history images, Teacher review proofs and Teacher task-detail proofs. All seven receive narrow domain routes; their old metadata fields remain compatible and frontend adoption is explicit. No affected actor is granted generic Files access.

## Authorization families (used by every inventory row)

Every private-content route retains JWT, trusted request context, actor, scope and the permissions stated in its row. Authorization is resolved before stat/read and re-resolved after the first provider byte, before headers. HEAD and 416 also re-resolve authority without opening the object. Bucket/key/name/MIME/size must still match. Revocation after delivery begins cannot recall delivered bytes; each subsequent request, including a range, re-authorizes.

The seven new avatar, reward catalog/history and Teacher proof reads (V, R1, R2, T1 and T2) also require `File.studentCredentialSecretArtifacts: { none: {} }`, preserving the existing generic Files sensitive-artifact boundary. A domain pointer does not grant authority to export Student credentials. An HTTP regression links the same synthetic File to a credential batch and verifies 404 with no object read for all seven domain paths and generic Files.

## Metadata consumers and justified no-change surfaces

The additional GET inventory includes metadata/control reads in every file-bearing domain. JSON endpoints do not become binary endpoints. The following family evidence controls their exact classifications in the table:

- **Academic metadata**: School `AcademicContentPresenter` and actor academic read models expose file/asset IDs, policy and preview support without storage coordinates. Student/Parent current and Teacher current/history transport is covered above; School management can use F. Snapshot/task/exam attachment metadata does not bypass domain visibility.
- **Communication metadata**: shared app attachment presenter exposes compatible legacy paths and additive actor `authorizedDownloadContentPath/authorizedPreviewContentPath`; School core consumers use F. Message visibility remains in actor resolvers. Contact avatars are null. Announcement presenters expose attachment IDs/name/MIME, with no byte/capability URL; their existing privacy tests forbid storage coordinates/download URL. No authorized announcement-download contract is invented here. A frontend attempting an unsupported generic actor fallback must not do so; request a separately authorized domain feature if actual evidence shows a need.
- **Homework/assessment metadata**: Student assignment attachments have H. School assignment, question, answer/submission and assessment attachment records expose IDs/metadata for authorized School F downloads. Teacher and Parent homework/exam read models expose IDs/metadata, with no signed or direct download URL in source. Their metadata reads are not evidence of a failed byte endpoint; introducing new actor file privileges is outside this compatibility change. Do not construct generic actor Files URLs from bare IDs.
- **Proof metadata**: Parent task proof uses P; Teacher review and task-detail proof use T1 and T2 respectively. Student own task proof is metadata only, without a download path or capability; no new Student task file-read feature. School reinforcement review metadata can use F under its existing School permission.
- **Rewards/profile**: Student own profile avatar uses V. Student/Parent reward catalog uses R1 and historical redemption uses R2. Teacher/Parent profile, app home/classroom/children/contact/hero image fields are currently null; no private URL exists to remediate. Shared reward metadata retains generic paths for compatibility; web must choose the correct actor/context-specific replacement.
- **Other School metadata**: attendance-excuse presenter `downloadUrl` and Student-document presenter paths target F; new F content resolves their byte-transport gap without changing their domain list/read guards. Admissions document metadata similarly uses the School file boundary. Branding metadata points to explicitly public B. Learning-media status/upload metadata exposes verification state, not an arbitrary private read capability. Bulk import/credential workers' object reads are internal jobs, not browser routes.

## Shared transport and security contract

`PrivateMediaContentService` → `StorageService` → `ObjectStoragePort` → GCS/MinIO is the sole private-byte transport. No service-account credentials, signed URL, storage bucket/key, internal provider error/cause or object generation/version is exposed by a content response. ETag is an opaque hash of provider identity/size. File coordinates are internal descriptors only. Domain 404/403 behavior is retained.

200 sends full exact bytes. Single `bytes=start-end`, `bytes=start-` and `bytes=-suffix` return 206 with exact length/Content-Range; oversized end/suffix is clamped. Invalid unit, syntax, reversed/out-of-bounds/unsafe integer, zero suffix, empty-file range or multipart returns bodyless 416 and `bytes */total`, without opening the object. A range is not constrained by the verifier's separate 1 MiB `readObjectRange` cap; offset/length must be safe positive integers. No small-file replacement cap is introduced.

HEAD uses the GET authorization/presentation and stat metadata, returns 200/full Content-Length without body/object read, and ignores Range. If-Range accepts only the exact emitted strong opaque ETag. Mismatch, weak ETag or HTTP date falls back to full 200; Last-Modified/date validators are not advertised. No general If-None-Match/304 contract is added. `Cache-Control: no-store, private, max-age=0`, `nosniff`, safe ASCII filename plus RFC 5987 Unicode filename\*, Accept-Ranges, MIME, Content-Length and appropriate Content-Range are set. CR/LF/control/path/quote characters and malformed surrogates cannot inject headers.

GCS selects the exact string generation, streams explicit start/end, and disables SDK decompression for raw representation reads. MinIO uses streaming getPartialObject with offset/length and versionId when present. Versioned reads pin stat/GET; unversioned ETag reads re-stat after the first byte to detect changed identity/size before headers. Missing or stale size/identity returns sanitized 404. The provider's read is one snapshot; this does not add object versioning to deployed infrastructure.

Initialization (stat, source open, first byte, authority recheck) is bounded to 10 seconds. Not-found is sanitized 404; other pre-header provider failures/timeouts are sanitized 503. Full transfer duration is governed by existing HTTP/runtime timeouts. Streams propagate backpressure, use 64 KiB output high-water marks, and destroy source on response close/abort. Exact byte counting rejects short/excess bodies. Final advertised bytes are withheld until EOF, so late failure/excess cannot masquerade as a complete Content-Length response. Post-header failures terminate the connection and emit only a fixed sanitized stream-failure event, never append JSON to binary bytes.

Academic policy still defaults to **536,870,912 bytes (512 MiB)** and caps at **10,737,418,240 bytes (10 GiB)**. Other domains retain their own existing upload policies. The proxy accepts an authorized admitted stored File, not arbitrary new formats or unlimited upload sizes. Streaming is constant in total file size, subject to provider chunk sizes, Node/TLS buffers, concurrent requests and deployed runtime capacity.

## Integration obligations

1. Keep the domain catalogs distinct: Homework SHORT_TEXT, LONG_TEXT, SINGLE_CHOICE, MULTIPLE_CHOICE, TRUE_FALSE, FILL_IN_BLANK, MATCHING, MEDIA, ORDERING, NUMERIC, MATH_EXPRESSION; Grades MCQ_SINGLE, MCQ_MULTI, TRUE_FALSE, SHORT_ANSWER, ESSAY, FILL_IN_BLANK, MATCHING, MEDIA, ORDERING, NUMERIC, MATH_EXPRESSION. Use the existing canonicalType/interaction and legacy fallback fields as defined by each DTO; do not collapse single/multiple choice or short/essay behavior.
2. Preserve persisted option/question identity. Grades option UUIDs remain canonical for selection. Homework embedded stable identities remain domain-specific. Reordering/display grouping does not rewrite child/answer IDs. Groups are non-answerable display containers; their points are derived from canonical children and never added twice.
3. Author-private key/metadata belongs only on authorized author surfaces. Ordinary Teacher review, Student and Parent responses cannot be used to reconstruct a key. Preserve required/optional metadata, SQL NULL versus JSON null versus omission, closed answer grammars and historical flat contracts. Do not send arbitrary correctness JSON to public views.
4. Render only the approved Safe Rich AST grammar with its accessibility and bilingual/RTL fields. Preserve legacy plain-text fallback on safe historical reads. Use resource-bound asset references and existing GET/HEAD/Range endpoints; never interpret a File ID, provider key, bucket or generic files download permission as resource ownership. Existing retained historical references continue to protect physical File lifetime.
5. Use responseConfig only on its approved short/long-text families. TEXT_ONLY, FILE_ONLY, AUDIO_ONLY, TEXT_OR_FILE, TEXT_AND_FILE and FILE_OR_AUDIO have different final completeness rules. A valid ready/bound File or Audio response does not need fake text. Assignment-level attachments and Student submission/answer attachments are distinct resources. Handle deleted/unlinked/stale/wrong-owner files and terminal/replayed submissions explicitly.
6. Teacher Grades authoring remains opt-in: grades.teacher_authoring.manage exists once and is absent from all seven default roles. Eligible writes require the exact live owned CLASSROOM allocation, creator, subject/year/term/school/organization, DRAFT/unlocked/no-attempt state and live membership/grant at commit. Existing management creation/publication authority is separate. An otherwise default Teacher must remain fail-closed; opt-in alone does not create assessment/publish rights.
7. Manual review/finalization and explicit GradeItem synchronization remain separate actions. Objective evaluation alone cannot award points or sync. APPLY and reasoned OVERRIDE use current versioned evidence; stale/duplicate decisions are conflicts. MCQ_MULTI adds no partial-credit scheme; NUMERIC adds no inferred tolerance/conversion; unproved/undefined mathematical expressions require rejection or manual review according to the current author/evaluator contract.
8. Grades review policy NONE denies detailed review; DETAILS excludes keys; KEYS requires current key approval plus release authority. Paper approval and key approval are separate. Re-fetch after revocation; legacy Grades/Exams cannot bypass it. Related Parent access additionally requires the current guardian/enrollment relation. Homework retains its separate legacy Parent review contract; this work grants no new Parent Homework Rich/protected-media surface.
9. Treat authorization 403/404 as non-disclosing. Preserve established 400 validation and 409 lifecycle/version conflicts. Do not automatically replay final submit, apply, override or sync as if a failure guaranteed no commit; use stable IDs and current state. The corrected sync now rolls its GradeItem back if its committed audit cannot be written.
10. Verify full GET 200, permitted Range 206, invalid Range 416, secure content type/disposition, no-store/nosniff headers and stream abort handling. Existing HEAD policy returns authorized full-length metadata with 200 and ignores Range. Media acceptance here uses isolated real objects and test-only security attestation; it is not Production scanner/provider approval.

Frontend/mobile owners should execute actual author -> publish -> Student save/upload/submit -> Teacher review/finalize -> explicit sync -> approved Student/Parent release/revoke journeys for both domains, all applicable modes, Arabic/RTL/accessibility, stable pagination/IDs and supported private previews. Include wrong actor/tenant, stale permissions, missing object, aborted stream and replay handling. Record app/version/device/source SHA and actual results before changing the two NOT_CERTIFIED client/product outcomes.

## A1 accepted design

- Exactly three new enums and two nullable fields; no tables, indexes, triggers, relations, permissions or backfill.
- New-type public definition lives in the entire existing HomeworkQuestion.metadata value: definitionVersion=1, kind=fill/matching/media. Legacy five-type metadata is untouched. Keys live only in answerKey; structured Fill/Matching answers live only in answerJson; MEDIA retains bounded textAnswer and manual review.
- Stable question-local ASCII IDs (1..64), unique positive orders, <=50 structured items, per-blank/label <=1000, MEDIA text <=10000, safe NFC text. Closed plain JSON with depth/node/UTF-8 budgets. Fill segments associate exactly once and in canonical blank order; Matching right reuse=false and sufficient right cardinality. Accepted Fill variants are bounded; supplied keys must be complete and reference only their definition.
- Incomplete structural drafts are distinguished from complete definitions; final provided answers must be complete, including optional supplied answers. Only a genuinely absent optional answer remains absent. Pure MEDIA syntax does not prove ownership/READY or authorization.
- SQL NULL absence requires authoritative SQL-null evidence; JSON null/unknown/malformed/future values are invalid/withheld. Explicit tagged clear maps to Prisma.DbNull. No default runtime DTO or selector is expanded.
- A narrow callback transaction is necessary because the existing array transaction cannot inspect a current type and abort before target writes. Acquire only the assignment lock, then current question types, then the existing target/status mutations; never acquire an allocation lock after assignment. Do not redesign publication lifecycle/scoring/targets.

# OR02 — Policy, grants and authorization

The school policy starts in MANAGED with personal design and draft capabilities
available within the teacher's current assignment. AUTONOMOUS changes the
default official design/first publication rules. Correction publication still
requires review by default. IAM independently controls publishing permissions.

## Contracts

The [OpenAPI artifact](openapi.json) was generated by Nest from the registered
configuration routes. It covers 18 operations in the school and teacher
Official Results namespaces. The [v1.0 inventory](contracts/endpoint-catalog.json)
tracks the remaining operations. Period and group lists default to UUID
ascending, with UUID descending available explicitly. Policy history uses
descending revision, and the grant list uses UUID ascending.

Policy preview binds the proposal, policy version, affected scope and current
structural sheet revisions. Its confirmation repeats the impact evaluation and
compares the digest. Command receipts preserve retries within the actor,
school, operation and key. A reused key with a different payload returns a
conflict. Activation, receipt and audit use one transaction.

A scoped rule selects settings by containment across academic, group and
reporting-period selectors. Incomparable conflicting settings require an
explicit intersection. School-wide publication suspension applies above all
scoped rules. The OR05 and OR08 workflows own candidate and import impact data.

## Current authority

Management and teacher surfaces require the existing authenticated school
context. The final transaction loads the active user, membership, role
permissions, school and organization. Policy activation takes the exclusive
side of the school-row lock used by commands. Teacher writes lock the current
exact allocation through the Academics operational write gate. A custom group
or year period requires an explicit current scoped grant. Archived correction
windows bind an actor, a slot and a release unit, with a maximum 24-hour expiry.

Staff routes advertise capabilities with current IAM, policy, scope and period
information. These are read hints. Entry, imports and publication still use the
authorization repository at their final write boundary.

## Reference data

The canonical permission catalog adds 27 `official_results.*` permissions.
The teacher system role receives scoped draft, template, import/export, review
submission, history and published-read permissions. Its direct publication
and corrected-publication permissions require authorized opt-in. Student and
parent system roles receive `official_results.results.view` as their only
permission in this namespace. School and organization administration retain
the existing system-role catalog rules.

Reference-data reconciliation uses the existing controlled bootstrap at rollout.
For the isolated fixture, the separate Prisma seed installed 271 total
permissions and 7 system roles.
